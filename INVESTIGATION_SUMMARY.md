# Build System Integration Investigation - Issue #31

## Investigation Date
2025-12-26

## Objective
Verify that GCC's build system correctly invokes the Metal backend when `-foffload=metal` is specified.

## Critical Issues Found

### 1. Missing Metal Support in configure.ac
**File:** `gcc/configure.ac` (lines 1174-1186)

**Problem:** The offload target validation case statement only recognized `amdgcn*` and `nvptx*`. Any attempt to configure with `--enable-offload-targets=metal` would fail with "unknown offload target specified" error.

**Fix Applied:** Added Metal case to the offload target validation:
```bash
metal*)
    omp_device_property=omp-device-properties-metal
    omp_device_property_tmake_file="${omp_device_property_tmake_file} \$(srcdir)/config/metal/t-omp-device"
    ;;
```

**Impact:** Without this fix, Metal backend could never be enabled as an offload target during GCC configuration.

### 2. Missing GOMP_SELF_SPECS Definition
**File:** `gcc/config/metal/metal.h`

**Problem:** Metal.h did not define GOMP_SELF_SPECS, which is required for offload-only targets. This macro is used by gcc.cc to avoid adding pthread linkage for OpenMP/OpenACC support.

**Fix Applied:** Added definition following NVPTX pattern:
```c
/* Avoid the default in ../../gcc.cc, which adds "-pthread", which is not
   supported for metal.  */
#define GOMP_SELF_SPECS ""
```

**Impact:** Without this, the driver might attempt to add pthread flags incorrectly.

### 3. Missing OMP Device Properties Build Rule
**File:** `gcc/config/metal/t-omp-device` (NEW FILE)

**Problem:** The configure.ac expects each offload target to provide OMP device properties via a Makefile fragment. This file was completely missing for Metal.

**Fix Applied:** Created new file with Metal device properties:
```make
omp-device-properties-metal:
	echo kind: gpu > $@
	echo arch: metal >> $@
	echo isa: msl_2_4 msl_3_0 msl_3_1 >> $@
```

**Impact:** OMP device property queries would fail for Metal target.

### 4. Generated configure Script Out of Sync
**File:** `gcc/configure` (lines 8344-8360)

**Problem:** The generated configure script (auto-generated from configure.ac) also needed the Metal case statement added.

**Fix Applied:** Added matching Metal case to generated configure script.

**Note:** This file is normally regenerated by autoconf, but was updated directly to maintain consistency.

## Conclusion

The Metal backend had correct target registration in config.gcc and proper mkoffload integration, but was missing three critical build system components:

1. Offload target validation in configure.ac/configure
2. GOMP_SELF_SPECS driver specification
3. OMP device properties build rule

All issues have been fixed following the established NVPTX pattern. The Metal backend should now integrate correctly with GCC's build system when configured with `--enable-offload-targets=metal`.
